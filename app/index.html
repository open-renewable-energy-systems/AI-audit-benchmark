SAGE · Standards Audit & Gap Evaluator ·

Multi-model audit of microgrid standards for AI-agent readiness — SAGE finds the gaps, GAIFARE fills them.

First time here? Three steps:

  1. Set up models — open ⚙ Model settings below. Local mode uses your own Ollama (and the claude/codex CLIs via python3 runner/bridge.py); Web mode uses OpenRouter or any OpenAI-compatible service with your API key. Three regionally diverse models are preselected. Click Test on each model until you see a green ✓.
  2. Run an audit — pick the standards and runs-per-model (1 for a quick look, 3 for official numbers), then ▶ Run audit. Each model scores each standard 0–3 on four agent-readiness dimensions, citing the clauses it relies on.
  3. Read the gap map — your results appear in the table above (● rows). Click any cell for each model's evidence; click a column header for what that dimension means. See the glossary under the map for score / evidence / rationale / confidence.

Glossary — what the numbers and columns mean
Score (0–3)
The model's own judgment of how well the standard covers a dimension: 0 absent · 1 implicit (inferable, no clause states it) · 2 partial · 3 explicit. The app never scores anything itself — it aggregates the models' judgments.
Evidence
The clause/section the model cites for its score (or "none"). Cited from the model's own knowledge in knowledge-only runs — citations can be wrong or invented, so they must be verified against the actual document. Feeding the standard's text (document-fed) forces citations from the real text.
Rationale
The model's one-sentence justification for the score.
Conf.
The model's self-reported confidence (0–1), averaged over its runs. A signal, not proof — a model can be confidently wrong. Evidence checking and cross-model agreement are the real safeguards.
Cell value
Per model: median of its runs. Per cell: median of the model medians when they agree within ±1 — otherwise contested (hatched, no number claimed).
⚠ unstable
One model's runs disagreed with each other by more than 1 — its score for that cell is not reproducible.
● live row
Produced by an audit run in this browser session. Published rows come from results committed in the repo.
knowledge-only vs document-fed
Whether the model answered from its training knowledge alone, or was given the standard's text to cite from. All built-in standards run knowledge-only; only custom standards with pasted/uploaded text are document-fed. Every exported result records which.
